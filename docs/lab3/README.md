# Лабораторная работа № 3

Вариант 15 по дисциплине «Управление данными». Предметная область по заданию — пилоты, штурманы, рейсы и полёты. Решение использует PostgreSQL 16 и создаёт отдельную схему `lab3_v15` внутри выбранной базы.

[Отчёт для защиты](report.md) содержит формулировки, SQL и результаты выполнения каждого задания обоих уровней.

## Запуск

Выполните из корня репозитория в терминале с доступом к PostgreSQL:

```sh
createdb vetcare_lab3
psql -X -d vetcare_lab3 -f docs/lab3/run.psql
```

Команды используют настройки подключения PostgreSQL из окружения. Если параметры подключения заданы отдельно, передайте те же параметры в `createdb` и `psql`. Для повторного полного прогона используйте новую пустую базу. Создание схемы, загрузка, запросы и изменения выполняются в одной транзакции. При ошибке изменения прогона откатываются.

| Файл | Назначение |
| --- | --- |
| [01_schema.sql](01_schema.sql) | Схема, таблицы и ограничения целостности |
| [02_seed.sql](02_seed.sql) | Исходные строки варианта 15 |
| [03_level1.sql](03_level1.sql) | Уровень 1, задания 3–9 |
| [04_level2.sql](04_level2.sql) | Уровень 2, задания 1–6 |
| [run.psql](run.psql) | Точка запуска для `psql` |

Чтобы показать отдельный запрос уровня 2 на защите, подключитесь к созданной базе и выполните `SET search_path TO lab3_v15;`. Затем вставьте нужный запрос из файла. Запросы 1.3–1.7 выполняются до пересчёта часов, а уровень 2 — после него. Повторный запуск 1.8 на готовой схеме повторно умножит часы на коэффициент сложности.

## Данные и трактовки задания

- Из приложения загружены 5 пилотов, 6 штурманов, 7 рейсов и 17 записей полётов. Для поля даты в источнике есть только месяц. Он хранится числом от 1 до 12.
- Для отсутствующих коэффициентов сложности используется формула `1 + (время рейса в часах − 1) × 0,1`. Название авиаотряда «Нижегродский» у рейса «Москва» исправлено на «Нижегородский».
- «Более одного раза» считается по сумме вылетов. «С февраля» включает февраль, «до декабря» исключает декабрь.
- В 1.9 процент вычисляется по скорректированным в 1.8 часам. Значение может превышать 100%, если часы превышают лимит. При добавлении новых записей в готовую схему нужно указать вычисленный процент.
- В 2.4б московские авиаотряды распознаются по названию «Московский» с возможным числовым суффиксом. В 2.4г проверяется каждая комбинация нужного рейса и штурмана с лимитом больше 48 часов.
- В 2.5б каждый подходящий рейс учитывается один раз. В 2.5г вылеты считаются по всем рейсам подходящего пилота в Хабаровск, а условие о работе с Самариным проверяется по всем его полётам.
