# Дашборд в DataLens

Дашборд клиники на четырёх вкладках: **Бизнес**, **Неявки**, **Клиенты**, **Эксперимент**. Данные — представления `metrics.dashboard_*` из [`dwh/metrics/09_dashboard.sql`](../dwh/metrics/09_dashboard.sql), выгруженные в CSV.

Почему файлы, а не прямое подключение к базе: DataLens работает в облаке и не видит PostgreSQL в локальном Docker. Выгрузка проще и безопаснее — не нужно открывать базу в интернет и хранить пароль в DataLens.

## 1. Получить CSV

Любой из двух способов:

- **Локально:** `make all && make export` — файлы появятся в `dwh/export/` (в git не попадают).
- **Из CI:** GitHub → Actions → последний зелёный запуск → внизу страницы артефакт **dashboard-data**.

| Файл | Строк | Одна строка — это | Для чего |
| --- | ---: | --- | --- |
| `visits.csv` | ~27 тыс. | прошедший приём | почти все чарты: выручка, приёмы, неявки, врачи; фильтры по периоду, филиалу, врачу |
| `cohorts.csv` | 300 | когорта × месяц жизни | матрица удержания |
| `lifecycle.csv` | 24 | месяц с первого визита | кривые удержания и LTV |
| `owners.csv` | ~4 тыс. | клиент | статусы оттока, список «кому напомнить» |
| `experiment.csv` | 2 | группа A/B-теста | доля неявок с доверительным интервалом |
| `experiment_weekly.csv` | 72 | неделя × группа | неявки по неделям и накопленно |
| `experiment_naive.csv` | 4 | сравнение × группа | ловушка наивного сравнения |

## 2. Подключение и датасеты

1. [datalens.ru](https://datalens.ru) → создайте воркбук **VetCare**.
2. **Создать → Подключение → Файлы**, загрузите все 7 CSV (лимит — 10 файлов на подключение). Параметры: кодировка `utf-8`, разделитель — запятая, заголовок — да. Проверьте типы: `visit_date`, `month`, `cohort_month`, `week_start`, `last_visit_date` — **Дата**; `revenue`, `*_pct`, `ltv` — **Дробное число**; `is_*`, `month_n` — **Целое число**.
3. Создайте 7 датасетов — по одному на файл, с теми же именами.
4. В датасете **visits** добавьте вычисляемые поля (кнопка «+ Добавить поле»):

| Поле | Формула | Смысл |
| --- | --- | --- |
| Выручка | `SUM([revenue])` | сумма оплат после скидок |
| Приёмов | `SUM([is_completed])` | состоявшиеся приёмы |
| Средний чек | `SUM([revenue]) / SUM([is_completed])` | выручка на состоявшийся приём |
| Доля неявок, % | `SUM([is_no_show]) * 100 / (SUM([is_completed]) + SUM([is_no_show]))` | неявки среди неотменённых записей |
| Доля отмен, % | `SUM([is_cancelled]) * 100 / COUNT([visit_id])` | отмены среди всех записей |
| Активные клиенты | `COUNTD_IF([owner_id], [is_completed] = 1)` | клиенты с хотя бы одним состоявшимся приёмом |
| Приёмов в день | `SUM([is_completed]) / COUNTD([visit_date])` | загрузка врача, имеет смысл в разрезе врача |

Доли считаются из сумм, а не средним по строкам, — так они остаются верными в любом разрезе и при любом фильтре.

## 3. Чарты

Создаются через **Создать → Чарт** на нужном датасете. В скобках — секции визарда.

### Вкладка «Бизнес»

| Чарт | Тип | Настройка |
| --- | --- | --- |
| Выручка | Индикатор | (Показатель) Выручка |
| Приёмов | Индикатор | (Показатель) Приёмов |
| Средний чек | Индикатор | (Показатель) Средний чек |
| Активные клиенты | Индикатор | (Показатель) Активные клиенты |
| Выручка по месяцам | Линейная диаграмма | (X) `month`, группировка по месяцу; (Y) Выручка; (Цвета) `branch_name` |
| Выручка по услугам | Линейчатая диаграмма | (Y) `visit_type`; (X) Выручка; сортировка по выручке |
| Средний чек по месяцам | Линейная диаграмма | (X) `month`; (Y) Средний чек |
| Врачи | Таблица | `doctor`, `specialization`, `branch_name`, Приёмов, Выручка, Средний чек, Доля неявок %, Приёмов в день; заливка-градиент на Выручке |

### Вкладка «Неявки»

| Чарт | Тип | Настройка |
| --- | --- | --- |
| Доля неявок | Индикатор | (Показатель) Доля неявок, %; фильтр `ab_group` ≠ «тест (SMS)» |
| По дню недели | Столбчатая диаграмма | (X) `weekday_name`, сортировка по `weekday`; (Y) Доля неявок, % |
| По сроку записи | Столбчатая диаграмма | (X) `lead_time`; (Y) Доля неявок, % |
| День × час | Сводная таблица | (Строки) `weekday_name`; (Столбцы) `visit_hour`; (Показатели) Доля неявок, %; (Цвета) Доля неявок, % — тепловая карта |
| По виду животного | Линейчатая диаграмма | (Y) `species`; (X) Доля неявок, % |

На всех чартах вкладки, кроме эксперимента, исключите `ab_group` = «тест (SMS)»: напоминания снижают неявки и смешали бы эффекты.

### Вкладка «Клиенты»

| Чарт | Датасет | Тип | Настройка |
| --- | --- | --- | --- |
| Матрица когорт | cohorts | Сводная таблица | (Строки) `cohort`; (Столбцы) `month_n`; (Показатели) `retention_pct`, агрегация «Среднее»; (Цвета) `retention_pct`; фильтр `month_n` ≤ 12 |
| Удержание по месяцам жизни | lifecycle | Линейная диаграмма | (X) `month_n`; (Y) `retention_pct` |
| LTV по месяцам жизни | lifecycle | Столбчатая диаграмма | (X) `month_n`; (Y) `ltv` |
| Статусы клиентов | owners | Кольцевая диаграмма | (Цвета) `status`; (Показатели) количество `owner_id` |
| Отток по числу животных | owners | Нормированная столбчатая | (X) `pets`; (Y) количество `owner_id`; (Цвета) `status` |
| Кому напомнить | owners | Таблица | `owner_id`, `last_visit_date`, `days_since_last_visit`, `visits_completed`, `revenue`; фильтр `status` = «засыпает»; сортировка по `revenue` ↓ |

### Вкладка «Эксперимент»

| Чарт | Датасет | Тип | Настройка |
| --- | --- | --- | --- |
| Неявки по группам | experiment | Таблица | `ab_group`, `not_cancelled`, `no_shows`, `no_show_pct`, `ci_low_pct`, `ci_high_pct`, `cancelled_pct`, `revenue_per_booking` |
| Неявки в контроле / тесте | experiment | Индикатор ×2 | (Показатель) `no_show_pct`; фильтр по `ab_group` |
| Накопленная доля неявок | experiment_weekly | Линейная диаграмма | (X) `week_start`; (Y) `cumulative_no_show_pct`; (Цвета) `ab_group` |
| Неявки по неделям | experiment_weekly | Столбчатая диаграмма | (X) `week_start`; (Y) `no_show_pct`; (Цвета) `ab_group` |
| Ловушка наивного сравнения | experiment_naive | Столбчатая диаграмма | (X) `comparison`; (Y) `no_show_pct`; (Цвета) `sms` |

Цвета групп одинаковые на всех чартах вкладки: контроль — синий, тест — оранжевый.

## 4. Дашборд

1. **Создать → Дашборд**, в настройках включите вкладки: Бизнес, Неявки, Клиенты, Эксперимент.
2. Сверху на вкладках «Бизнес» и «Неявки» — селекторы по датасету **visits**: `visit_date` (календарь, диапазон), `branch_name`, `specialization`. Селекторы влияют на все чарты этого датасета на вкладке.
3. Раскладка каждой вкладки: строка индикаторов → два главных графика рядом → таблица на всю ширину.
4. Под заголовком каждой вкладки — **текст** с выводом в одну-две строки, чтобы дашборд читался без автора:
   - Бизнес: «Выручка за год выросла на 5–44% к прошлому году; хирургия — 7% приёмов и 34% выручки».
   - Неявки: «Неявок больше всего в понедельник (13,7%) и при записи за 15+ дней (15%)».
   - Клиенты: «В следующем месяце после первого визита возвращаются 29% клиентов; LTV за год — 14 тыс. ₽; у владельцев 3+ животных отток в 5 раз ниже».
   - Эксперимент: «SMS снижают неявки с 9,1% до 6,9% (−24%, p = 0,0001). Наивное сравнение по всем приёмам занижает эффект на треть». Ссылка на [ноутбук](../analysis/ab_sms_reminders.ipynb).

## 5. Публикация

Меню дашборда **⋯ → Поделиться → Публично → Публичный доступ**, связанные объекты публикуются вместе с ним, затем **Скопировать ссылку**. В данных нет персональной информации — имена клиентов в выгрузку не попадают, только номера.

Ссылку и 2–3 скриншота (`dashboard/screenshots/*.png`) добавьте в корневой [README](../README.md).

## Проверка

- Выручка на индикаторе без фильтров — 65,0 млн ₽, как `SELECT sum(revenue) FROM metrics.dashboard_visits`.
- Доля неявок в эксперименте — 9,13% и 6,91%, как в ноутбуке.
- Если цифры не совпадают, чаще всего виновата агрегация: доля посчитана средним по строкам, а не через суммы.
